# 영수증 OCR API 설계 및 구현 결정사항

[OpenAPI 명세](openapi.json)의 `POST /api/v1/proxy/ocr` 계약을 보충하고 구현 시 확인할 사항을 기록합니다. 구현 목표와 계약의 기준은 OpenAPI이며, 내용이 충돌하면 OpenAPI를 따릅니다. 현재 Python 서버에 이 API가 구현되었다는 의미는 아닙니다.

## 확정된 계약

- Bearer 인증과 multipart `files` 배열을 사용하며 파일은 1~10개입니다.
- JPEG·PNG·HEIC·PDF를 허용하고 파일당 크기는 최대 10,000,000바이트입니다.
- 파일별 OCR 호출 제한은 60초이며 자동 재시도하지 않습니다.
- 일부 파일이 실패해도 입력 순서대로 파일별 성공·실패 결과를 반환합니다.
- OCR 결과는 거래 필드와 같은 store_name/date/time/amount를 사용하고 거래를 자동 저장하지 않습니다.
- 선택적 `Idempotency-Key`를 지원합니다. 성공 응답을 24시간 보관하여 같은 요청의 재시도에서 OCR을 다시 호출하지 않습니다.

## 구현할 때 결정할 사항

전체 요청 제한 시간과 파일 처리 방식은 실제 OCR 제공자와 배포 환경을 측정한 뒤 정합니다. 구현할 때 1개와 10개 파일 요청의 처리 시간, 메모리 사용량, 외부 API 동시 호출 제한, 앱·프록시의 연결 제한을 확인합니다.

측정 결과 동기 요청으로 안정적으로 완료할 수 있으면 전체 제한 시간과 최대 병렬 처리 수를 정해 이 문서와 OpenAPI에 반영합니다. 최악 처리 시간이 앱이나 프록시의 요청 제한을 넘으면 `202 Accepted` 기반 비동기 작업 생성·상태 조회 API로 전환합니다. 이 결정을 내리기 전까지 OpenAPI는 파일별 60초 제한만 보장하며 전체 요청 제한 시간이나 순차·병렬 처리를 보장하지 않습니다.
