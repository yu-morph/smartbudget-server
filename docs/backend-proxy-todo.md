# OCR·소비 분석 백엔드 작업 현황

API 계약은 [OpenAPI 명세](openapi.json)를 기준으로 한다. 2026-11-19 개발 VM과 Azure 확인은 [PR #19](https://github.com/yu-morph/smartbudget-server/pull/19) 당시 구현을 대상으로 했다. 이 문서는 구현 상태와 개발 VM 검증 상태를 구분한다.

## OCR 프록시

- [x] Document Intelligence 영수증 모델, 키 인증 및 HEIC의 PNG 변환을 적용했다. 서버 설정과 의존성은 `.env.example`과 [서버 설명서](server.md)에 기록했다.
- [x] Bearer 인증, 파일 1~10개, 지원 형식과 실제 내용, 파일당 10,000,000바이트 제한 및 정의되지 않은 필드를 검증한다.
- [x] 파일별 외부 호출에 60초 제한을 두고 자동 재시도하지 않는다. 처리 가능한 결과는 입력 순서대로 반환한다.
- [x] 상호·항목·날짜·시간·총액을 변환하고 누락 값을 처리한다. 여러 영수증이 확인되거나 페이지 구분이 어려운 경우 실패 처리하며 거래를 자동 저장하지 않는다. OCR 필드가 누락된 경우 별도 영수증을 놓칠 가능성은 [OCR 설계](ocr.md)에 기록했다.
- [x] `Idempotency-Key`의 성공 응답 24시간 보관, 동일 요청 재사용 및 충돌을 처리한다. 중단된 요청은 자동으로 재호출하지 않고 복구 절차를 따른다.
- [x] 로컬에서 1개·10개 파일의 처리 시간과 메모리를 측정하고 프로세스당 외부 호출 최대 2개로 설정했다. 측정 범위는 [OCR 설계](ocr.md)에 기록했다.
- [x] 개발 VM의 독립 컨테이너와 DB에서 실제 Azure에 연결해 영수증 1개·10개와 소비 분석의 응답 시간 및 컨테이너 메모리를 측정했다. 결과와 시험 범위는 [OCR 설계](ocr.md)에 기록했다.
- [x] 같은 격리 환경에서 외부 OCR을 모의하여 약 9.95MB 파일 10개와 대용량 파일 동시 요청 두 건을 시험하고 시간·메모리를 측정했다.
- [x] VM에서 기존과 같은 Caddy 2.11.4를 별도 실행해 독립 컨테이너와 실제 Azure를 TCP로 연결했다. 실제 OCR 1개·10개와 두 동시 요청, 소비 분석이 성공했다. 공개 HTTPS 버전 응답과 HTTP→HTTPS 리디렉션도 별도로 확인했다.
- [x] 별도 Caddy 경로에서 외부 OCR을 모의해 약 9.94MB PNG 10개 요청과 대용량 동시 요청을 확인했다.
- [ ] 새 기능이 배포된 공개 HTTPS→Caddy→API→Azure 전체 경로와 장시간 사용자 부하를 검증하고 전체 요청 시간 제한 및 동기 유지 또는 비동기 전환을 결정한다. 현재 공개 서버에는 새 기능이 없다.
- [x] 공개 실제 한국 영수증 2장과 이를 나누거나 합친 PDF를 시험했다. 한 장의 총액 누락과 한 영수증의 두 페이지 분할 시 실패가 관찰됐다. 상세 결과와 출처는 [OCR 설계](ocr.md)에 기록했다.
- [ ] 더 다양한 실제 영수증과 여러 페이지 PDF로 정확도 및 영수증 구분 한계를 검증한다. 두 장의 시험만으로 인식률을 추정할 수 없다.

## 소비 분석

- [x] Foundry `gpt-6-luna` 배포와 키 인증을 사용하고, 새 리포트의 출력 형식은 XML 템플릿으로 지정한다. 호출 전체에 60초 제한을 두고 재시도하지 않으며, 오류 시 기존 리포트를 유지한다.
- [x] 기간, 선택적 앱 입력 및 거래일·유형·카테고리·금액을 담은 거래 행을 한 줄 JSON으로 전달한다. 사용자 ID·거래 ID·거래 시각·상호·메모·입력 출처는 거래 데이터에서 제외한다.
- [ ] 실제 Azure 배포에서 새 XML 템플릿의 섹션 준수율과 장기간 거래 분석의 토큰 사용량을 측정한다.
- [x] 한국 시간 기준 미래 기간과 주간·월간·연간 시작 조건을 검증하고 거래 없음 오류를 계약에 맞춘다.
- [x] `Idempotency-Key` 24시간 보관·재사용·충돌과 사용자·기간별 동시 생성 잠금을 적용한다.
- [x] 리포트 유일성 확보 및 기존 DB용 이전 스크립트를 마련했다. 기존 DB 이전 전 백업이 필요하며 중복 데이터가 있으면 자동 삭제하지 않고 중단한다.
- [x] 거래 생성·수정·삭제 시 리포트를 오래된 상태로 표시하고 생성 중 거래 변경의 경합을 검증했다.
- [x] 한국 시간 기준 일간·주간·월간·연간 자동 생성과 재시작·중단 복구 절차를 구현했다.
- [x] AI 배포의 설정된 요청·토큰 한도와 Azure 공개 소매 요금을 확인하고 예시 비용을 산정했다. 아래 비용 확인을 참조한다.
- [ ] 실제 청구 계약의 적용 단가·통화와 서비스의 예상 사용량을 확인하고 운영 예산을 산정한다.

## Azure 리소스와 비용 확인

2026-11-19 확인한 리소스는 `rg-smartbudget-dev-koreacentral`에 있다. OCR은 `smartbudget-docintel-dev-kc` S0, 분석은 `smartbudget-foundry-dev-kc` S0의 `gpt-6-luna` GlobalStandard 배포(용량 1), VM은 Standard_B1ms다. AI 배포의 `rateLimits`는 **60초당 요청 1회, 토큰 1,000개**다. 동시 요청이나 예약 생성이 이 한도를 초과하면 429가 발생할 수 있으며 현재 프록시는 자동 재시도하지 않는다. OCR의 리소스별 사용량 조회는 빈 목록이었다. [Microsoft의 S0 기본값](https://learn.microsoft.com/en-us/azure/ai-services/document-intelligence/service-limits?view=doc-intel-4.0.0)은 분석 15건/초, 결과 조회 50건/초이나 실제 조정 여부는 확인하지 못했다.

2026-11-19 [Azure 소매 가격 API](https://prices.azure.com/api/retail/prices?%24filter=armRegionName%20eq%20%27koreacentral%27%20and%20productName%20eq%20%27Azure%20Document%20Intelligence%27)에서 한국 중부 Document Intelligence S0 사전 구축 모델은 1,000페이지당 **USD 10**으로 조회됐다. [Microsoft의 GPT-6 요금 안내](https://azure.microsoft.com/en-us/blog/gpt-6-astra-sol-and-luna-for-production-agents-in-microsoft-foundry/)에서 Luna Global Standard 짧은 문맥은 입력 100만 토큰당 USD 0.10, 출력 100만 토큰당 USD 0.50이다. 예를 들어 OCR 1,000페이지는 USD 10, 분석 1,000회가 회당 입력 500·출력 200토큰이면 USD 0.15다. VM·스토리지·네트워크 비용과 세금은 제외한 가정이며 실제 계약 단가, 통화, 할인과 사용량에 따라 달라진다. 구독 사용량 응답만으로 AI 리소스의 실제 청구 단가·통화를 확인하지 못했다. 키·토큰이나 실제 영수증 내용은 문서에 기록하지 않는다.
